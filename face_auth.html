Face Authentication API Documentation

This documentation covers the Face Authentication system including endpoint reference and internal business logic.

POST /api/auth/face/register

Purpose

Register user face biometric data for future authentication.

Request Body

{
  "userId": "usr_123",
  "faceEmbedding": [0.245, 0.832, 0.421],
  "deviceId": "iphone-15-pro"
}

Success Response

{
  "success": true,
  "message": "Face registered successfully"
}

Error Response

400 Invalid face data
409 Face already registered
500 Server error

Business Logic

flowchart TD A[Receive Face Embedding] --> B[Validate User Session] B --> C[Check User Exists] C --> D[Validate Embedding Format] D --> E[Encrypt Biometric Data] E --> F[Save To Database] F --> G[Link To User Profile] G --> H[Return Success Response]

POST /api/auth/face/verify

Purpose

Authenticate user using face recognition.

Request Body

{
  "faceEmbedding": [0.245, 0.832, 0.421],
  "deviceId": "iphone-15-pro"
}

Success Response

{
  "success": true,
  "token": "jwt_token_here",
  "user": {
    "id": "usr_123",
    "name": "Rem"
  }
}

Error Response

401 Face not recognized
403 Liveness check failed
404 User not found
500 Server error

Business Logic

flowchart TD A[Open Camera] --> B[Capture Live Face] B --> C[Run Liveness Detection] C --> D[Convert To Embedding Vector] D --> E[Send Vector To Backend] E --> F[Validate Payload] F --> G[Fetch Stored Embeddings] G --> H[Compare Face Vectors] H --> I{Similarity Above Threshold} I -->|Yes| J[Generate JWT Token] J --> K[Store Login Session] K --> L[Return User Data] I -->|No| M[Authentication Failed]

Security Notes

  • Never store raw face image unless required
  • Store encrypted embedding vectors
  • Apply liveness detection against spoofing
  • Use HTTPS for all APIs
  • Apply JWT expiry
  • Audit failed authentication attempts
  • Use device binding when possible
